# DAY終了オートセーブ — 2026-11-12

実装とUnity Editor上の機能検証を完了。配布ビルドは作成していないため、配布アプリの実プロセス終了・再起動は未検証。

## 実装

- `RunSaveStore`: `persistentDataPath/AutoSave` に本ファイル・直前バックアップ・周回管理情報を保存。一時ファイルのflush後に置換する。保存・無効化・全削除を直列化し、世代変更後の古い書き込みを拒否。
- `RunSaveCodec`: 明示した44の周回状態、素材6種、次ステージ、ショップシード/リロール、レシピ選択をコピー。武器9件・パーツ35件はGUIDカタログで記録。配置・型・進行・チュートリアル情報を復元前に検証する。パーツ補正を再計算し、永続カード補正を別管理する。
- `RunSaveService`: DAYリザルト終了後にコピーを確定して非同期保存。新規出撃確定・門破壊・全ED・タイトルのデータリセットを接続。終了済み周回はファイルの管理情報とPlayerPrefsの終了IDで再開を防ぐ。
- `RunSaveRuntime.prefab`: Titleに配置し、シーン間で保持。SAVE表示と確認/失敗/再試行UIはすべて静的なPrefabオブジェクト。Unityオブジェクト生成コードは追加していない。
- SAVE表示は64×64の既存歯車、上の白文字、時計回り90度/秒。点は0.35秒周期、文字全体は0.5秒表示/0.5秒非表示。最低1.2秒、実時間で更新する。
- 保存失敗時は前回ファイルを保持し、再試行は失敗した同じJSONを使う。終了要求は保存処理を待ち、失敗時に「保存せず終了／戻る」を表示する。

## 試験で修正した点

- 破損から復旧後の保存で、正常バックアップを破損ファイルで置き換えないようにした。
- 保存失敗の通知から長いOSパスを除き、日本語の案内にした。初回保存失敗でも存在しない前回セーブがあると断言しない。
- 終了確認の取消をゲーム内でもEscで行えるようにした。
- 既存の`StartingWeaponSettingsController.warningWindow`がTitleで未設定だったため、リセット本体が成功してもUI更新で例外になっていた。未設定参照を保護して再試験成功。

## 制約と残確認

- Editorの停止・再生は実施済み。配布アプリのプロセス再起動、OS強制終了、配布対象OSでのファイル置換は未実施。途中書き込み/破損は一時フォルダのファイル障害試験で確認した。
- マウス/キーボードのOS入力注入は行っていない。UIボタンの既存イベントと取消メソッドを実行して検証した。
- Titleの既存開始武器切替の注意ウィンドウ自体は参照が未設定。今回の修正はリセットと設定画面が例外にならないための保護であり、その注意ウィンドウの再配置ではない。
- 新しい武器/パーツを追加する場合は、PrefabのGUIDカタログも更新する。新しい永続カード効果は保存ホワイトリストへの登録と往復確認が必要。

`Native*.cs.txt`は今回の退避済みテスト状態で使用したEditor用の手順で、プレイヤー進捗を変更する。再実行前にも実セーブとPlayerPrefsの退避・検証後の復元が必要。
