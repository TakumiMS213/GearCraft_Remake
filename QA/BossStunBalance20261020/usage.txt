Records and success criteria
*-bosses.csv: exact direct spawn request time to defeated, or observed native spawn
to defeated in full-day mode. Defeated requires observing HP<=0. A lost Unity object
without HP0 is unobserved despawn. Player death/gate destruction/timeouts are distinct.
*-stun.csv: threshold_damage is synchronous with production Damaged (after stun
state update). Records HP, BossStunCount, remaining seconds, LastStunHitPosition.
started/ended are frame observations; max root drift only includes active stunned
frames, excluding legitimate movement on the first resumed frame. Visual variation
and child smoke particle counts are sampled. A lethal hit may end a stun early.
*-particles.csv: actual first-seen BossStunExplosion root positions, compared to
LastStunHitPosition, not inferred from the enemy center.
*-samples/-geometry/-native-input CSV: runtime AI/HP/positions/attack acceptance.
summary.json contains only cases with a result; kill_seconds is null for failures.
60-second criterion applies only to actual defeated times. Survived is a separate
boolean. Do not synthesize a kill time from partial HP, timeout, or old DPS.

Cancellation and restoration
Write cancel-defense-batch.txt or cancel-native-survival.txt in this folder.
The next Editor update stops and drains batch/route callbacks and then stops Play.
Keep cancellation evidence until reviewed; remove only those own sentinels before
a later run. Do not clear all PlayerPrefs, import old plists, or alter saved assets.
After all measurements (and Play stops), execute RestoreSession.cs.txt.
It validates this Editor SessionState ID and hashes from the current backup,
restores/verifies all 16 typed keys, exact fixed timestep ticks, logger/DOTween,
GameView size index/list and clean Title. It refuses outstanding RUNNING/LOADING
markers and unsaved scenes. canonical-restoration.txt closes the session; no more
tests may start under that snapshot. Further tests require a new session directory.
Historical backups are never copied or restored.
