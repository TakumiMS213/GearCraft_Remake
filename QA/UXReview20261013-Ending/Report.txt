UX継続テスト・ターム7：EDの進行、初回解放、タイトルとギャラリー
実施日: 2026-10-13 JST
環境: Unity 6000.0.67f1 / macOS / Editor Play / Game画面1920×1080
状態: 3種類EDの初回・再達成、配置修正後の追試、元データ復元・停止後照合を完了。

観測と変更

1. EDの操作案内とキーボード経路
変更前: ED画面には操作対象のButtonがなく、初期選択もnull。左クリックだけで進行。
解放通知の案内も「クリックでタイトルへ」で、Enterから進行する経路がなかった。
変更後: Endingシーンに進行Buttonと案内を配置。既存MessageWindowにもButtonを追加。
クリックとSubmitを同じ進行処理へ接続し、表示中の操作対象へ選択を移す。
案内は「表示を完了」「次へ」「続ける」「タイトルへ」を状態に合わせて切り替える。
フェード中の操作では表示を完成させ、次の操作で次のページへ進む。
同フレームの二重進行、ロード中の操作、通知直後の読み飛ばしを防ぐ。
初回通知中は通常の進行Buttonと案内を隠し、黒背景とメッセージだけを表示する。
解放条件とED別画像の順序は既存の処理を使用。
対象: Ending.unity / EndingManager.cs / ImageSequenceViewer.cs

2. タイトル・ギャラリーの背景クリック後の選択
変更前: 使用中のInputSystemUIInputModuleの処理と同じ選択解除条件を使い、
Gallery Entry_0→null、Title GalleryIcon→nullを再現。次のフレームにもGalleryはnull。
表示中の項目が残っているのに、キー操作の選択先が失われていた。
変更後: 両シーンのDeselect On Background Clickをfalseに設定。
同じ経路で選択維持を確認し、DownでTitle StartButton→SettingButton、
Gallery Entry_0→Entry_1へ移動できることを確認。
対象: Title.unity / Gallery.unity の各InputSystemUIInputModule設定1項目。

3. 操作案内と本文の重なり
初期画面だけでは分からなかった重なりを、Bad/Normalの最終ページとスコア画面で確認。
案内背景を右下基準(-140,112)、690×64から、(-140,84)、690×44へ変更。
本文の最終行とED名の間に配置し、文字サイズ32を維持した。
変更後の3種類EDで、最終ページとスコアの計6枚を確認。本文とED名を隠さない。
True EDでは新聞イラストに重なるが、本文・ED名・スコア・操作アイコンは隠さない。

根拠と判断

Microsoft / Xbox Accessibility Guideline 112: UI navigation
https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112
選択移動を予測可能にし、対応する入力で画面を操作し続けられるようにする観点。
今回は背景クリックで選択先が失われる実測結果と、EDのSubmit経路欠落に適用。

Microsoft / Xbox Accessibility Guideline 114: UI context
https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/114
操作方法と実行後の結果を判断できる文脈の観点。
今回は表示完了・次ページ・タイトル帰還の案内を出し分ける判断に適用。

安藤昌也教授インタビュー / HIP
https://hiptokyo.jp/hiptalk/ux_design/2/
画面単体だけでなく体験の前後を含め、試作をユーザー評価につなげる方針を参考にした。
EDから解放通知、Title、Gallery、Title帰還までを検証単位にした。
これらは設計判断の根拠であり、利用者の理解度向上を実証したものではない。
